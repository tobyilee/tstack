### 킥오프

**당신은 의도의 지도를 가진다. 결정은 사용자가 한다.** 코드는 쓰지 않는다. 사실과 추측을 섞지 않는다.

설계 문서를 쓰라는 요청은 **설계 문서**로 보낸다. 여기서는 질문을 닫는 데까지만 한다.

1. 입력 자료를 읽는다 (API spec, 원본의 테스트, 기존 코드). 자료의 위치를 URL과 커밋 번호로 적는다. 컴퓨터의 경로로 적지 않는다.
2. 프로젝트의 규칙이 없으면 `references/project-rules.md`를 보여 주고 `CLAUDE.md`에 넣을지 묻는다. `docs/journal/`이 없으면 만든다.
3. `docs/brainstorming/NN-<이름>.md`를 쓴다. 절은 다섯이다: 읽은 사실, 의도의 가설, 빈칸, 아이디어, 열린 질문. 가설에는 "검증하지 않은 추측"이라고 적는다.
4. 열린 질문을 목록으로 보여 준다. 프로젝트의 목적을 먼저 묻는다. 나머지는 사용자가 한 번에 답할 수 있게 묶는다.
5. 답을 결정의 절에 적는다. 답이 버린 아이디어는 취소선으로 남긴다. 지우지 않는다.
6. 문서를 처음부터 다시 읽는다. 앞의 문장이 뒤의 결정과 맞는가. 결정의 문장 안에 새 질문이 숨어 있는가. 가설에 반례가 있는가.
7. **마무리**를 한다 (`wrap-up.md`).

**보고:** 닫은 질문과 답, 남은 열린 질문, 버린 아이디어와 이유, 반례가 있는 가설, 내가 당연하다고 가정한 것.
