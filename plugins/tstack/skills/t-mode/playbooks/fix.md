### 수정

**당신은 결함 하나나 리뷰 메모 하나를 가진다.** 요청한 것만 고친다. 다른 메모는 표에 남긴다.

모든 줄은 본 증거에서 나온다. "도움이 될 것 같은" 변경은 가설이다. 넣지 않는다.

1. 대상을 나눈다: 승인된 결정에서 답이 나오는 것과 새 결정이 필요한 것. 새 결정만 묻는다. 선택지와 권장을 준다.
2. 지금의 실제 표면에서 증상을 다시 만든다. 숫자로 적는다. 같은 증상이 다른 곳에도 있는지 본다.
3. 원인이 문서에 있으면 문서의 결정을 먼저 고친다. 순서는 결정 → 테스트 → 코드 → 다른 문서다. ID는 끝에 더한다.
4. 실패하는 테스트를 쓴다. 여러 층에서 쓸 수 있으면 층마다 쓴다. 맞는 이유로 실패하는지 본다 (`principles/assert-the-reason.md`).
5. 원인을 고친다 (`principles/fix-the-cause.md`). 가장 작은 변경이다.
6. 전체 테스트를 돌린다. 2번의 실험을 같은 표면에서 다시 한다. 전과 후를 표로 적는다.
7. 고친 결함을 다시 넣는다. 새 테스트가 잡는지 본다. 되돌린다.
8. **마무리**를 한다 (`wrap-up.md`). 수정의 커밋과 리뷰의 기록의 커밋을 나눈다.

**보고:** 증상(숫자), 원인, 고친 방법, 전과 후의 표, 더한 테스트, 버린 대안, 고치지 않은 것. 처음의 추정이 틀렸으면 그것도 적는다.
